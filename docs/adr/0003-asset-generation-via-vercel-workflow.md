# Sync Gemini for cream-ground generate; Vercel Workflow for post-steps

Illustration **generation** is a synchronous admin API call: Gemini Flash Image (`google/gemini-2.5-flash-image` via Vercel AI Gateway) edits anatomy + style reference images into a cream-ground kachō-e PNG, concurrent pool of a few poses at a time. Each successful PNG is uploaded to Convex immediately, then a durable **Vercel Workflow** runs post-steps for that pose: fal.ai BiRefNet matting → sharp mask/dims → AI verify (**xAI vision** via AI SDK) → stage cutout → species reaches `pendingReview` only when both poses have passed verify. Human approval remains a plain Convex mutation after both poses are staged. Cream-ground-then-mat and the kachō-e prompt spirit match AvianVisitors. Reference images stay on **stable public HTTPS URLs** for the generate window (visitor cutouts remain in private Convex storage).

**Supersedes** the Batchwork + xAI `grok-imagine-image-quality` generate plan: xAI rejects those models for batch processing, so Batchwork never delivered the intended discount path. Sync xAI edit was tried as a fallback; sync Gemini via AI Gateway won on cost and parity with the AvianVisitors pregen path. Residual Batchwork tables/poll routes may still drain leftover open jobs; new Generate traffic does not submit batches.

Considered and rejected: full pipeline inside one WDK run (holds the workflow open for slow image gen), Batchwork as sole orchestrator (cannot run fal/sharp), prompt-only generate without refs, short-lived Convex signed URLs as model inputs, and local-only scripts for admin regen.
