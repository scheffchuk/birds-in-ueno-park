# Batchwork (xAI) for cream-ground generate; Vercel Workflow for post-steps

Illustration **generation** is a provider batch job via [Batchwork](https://batchwork.dev/): `batch.images.edit()` with xAI `grok-imagine-image-quality`, anatomy + style reference URLs, one request per species×pose (`customId`). That buys ~50% batch pricing and avoids holding a workflow open for slow image gen. **Post-steps** stay a durable Vercel Workflow per result (or per species once both poses land): download the signed result URL promptly (~1h TTL) → fal.ai BiRefNet matting → sharp mask/dims → AI verify (**xAI vision** via AI SDK) → Convex upload → `pendingReview`. Human approval remains a plain Convex mutation after both poses are staged. Post-Workflows run **per pose** as soon as each Batchwork result arrives (download before ~1h URL expiry); the species reaches `pendingReview` only when both poses have passed verify. This supersedes running the full pipeline (including Gemini sync generate) inside one WDK run. Cream-ground-then-mat and the kachō-e prompt spirit are kept; the generate provider moves from Gemini to xAI so Batchwork can pass reference images (Gemini batch image create has no ref path; xAI edit does). Reference images are exposed on **stable public HTTPS URLs** for the batch window (cutouts remain in private Convex storage). Considered and rejected: Batchwork as the sole orchestrator (cannot run fal/sharp), prompt-only batch generate without refs, short-lived Convex signed URLs as batch inputs, and local-only scripts for admin regen.
