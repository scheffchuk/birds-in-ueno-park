# Locale via next/root-params; dual root layouts

Next.js 16.3 `next/root-params` lets Server Components read the `[locale]` segment without `setRequestLocale`. Public routes use `app/[locale]/layout.tsx` as a root layout; `/admin` uses `app/(unlocalized)/admin/layout.tsx` as a second root (English, outside Locale routing). Avoid a layout at `app/(unlocalized)/layout.tsx` — that registers as `/` and Next treats `/` as an ancestor of every other layout, so `[locale]` would stop being a root layout and root-params would not expose Locale. `i18n/request.ts` resolves Locale from root params (explicit override still wins); unknown segments `notFound()`; missing params fall back to JA only for the unlocalized tree. `global-not-found` covers document-level 404s when there is no single ancestor layout. Removed the client `HtmlLang` patch now that the public root sets `<html lang>` from Locale.
